# Portfolio Analyzer

**Учебный проект по анализу и оптимизации инвестиционного портфеля, частично реализованный с помощью искусственного интеллекта.**

Portfolio Analyzer — веб-приложение для изучения портфельной теории на исторических рыночных данных. В нём можно составить портфель, сравнить варианты распределения активов и посмотреть, как меняются доходность, риск и стоимость капитала при разных настройках.

Проект объединяет математические методы оптимизации, обработку финансовых временных рядов и разработку клиент-серверного приложения. Текущая реализация представляет собой учебный прототип.

## Цель и задачи работы

**Цель:** разработать инструмент, который позволяет на практике исследовать связь между составом портфеля, его доходностью и риском.

В рамках проекта реализованы следующие задачи:

1. Загрузка и подготовка исторических данных из открытых источников и пользовательских файлов.
2. Расчёт доходности, волатильности, коэффициента Шарпа и просадок портфеля.
3. Подбор весов активов по модели Марковица и построение эффективной границы.
4. Учёт валютных курсов, инфляции и периодической ребалансировки в индексном портфеле.
5. Визуализация и сравнение результатов, экспорт данных для дальнейшего анализа.
6. Разделение приложения на серверную и клиентскую части и подготовка автоматических тестов.

## Реализованные возможности

### Индексный портфель

Основной режим позволяет выбрать от 2 до 10 индексов, задать начальный капитал, период исследования и правила ребалансировки. Веса задаются вручную либо рассчитываются по критерию минимальной волатильности или максимального коэффициента Шарпа.

В каталоге доступны IMOEX, MCFTR, RGBITR, RUCBTRNS, S&P 500, Nasdaq 100, Dow Jones, Russell 2000, FTSE 100 и Nikkei 225.

- Зарубежные индексы пересчитываются в рубли по официальным курсам Банка России.
- Номинальная и реальная динамика капитала показываются с учётом месячного ИПЦ Росстата.
- Поддерживается ежемесячная, ежеквартальная и ежегодная ребалансировка, а также расчёт без неё.
- Денежный агрегат M2 отображается как отдельный ориентир для сравнения и не участвует в оптимизации.

### Анализ собственных данных

Дополнительный режим открывается кнопкой «Другие данные» и поддерживает:

- загрузку доходностей из Excel/CSV или котировок через MOEX ISS и Yahoo Finance;
- анализ от 2 до 50 активов;
- четыре режима оптимизации и построение эффективной границы с облаком случайных портфелей;
- сравнение до пяти портфелей по показателям и графикам;
- экспорт результатов в Excel, весов в CSV и диаграммы весов в PNG;
- сохранение портфелей в текущем браузере через IndexedDB.

## Теоретическая основа

Оптимизация основана на модели Марковица: ожидаемая доходность портфеля определяется доходностями активов и их весами, а риск — ковариационной матрицей доходностей. Для численного решения используется метод SLSQP из SciPy.

Во всех режимах действуют ограничения: вес каждого актива находится в диапазоне от 0 до 1, сумма весов равна 1. Короткие продажи не поддерживаются.

| Режим | Задача |
|---|---|
| Минимальная волатильность | Найти портфель с минимальной дисперсией |
| Максимальный коэффициент Шарпа | Максимизировать отношение избыточной доходности к риску |
| Заданная доходность | Минимизировать риск при целевой доходности |
| Ограничение риска | Максимизировать доходность при заданном пределе волатильности |

Все четыре режима доступны при анализе собственных данных. В индексном режиме реализованы ручные веса, минимальная волатильность и максимальный коэффициент Шарпа.

Основные показатели:

| Показатель | Способ расчёта |
|---|---|
| Среднегодовая доходность | `mean(r_p) × k` |
| Годовая волатильность | `std(r_p) × √k` |
| Коэффициент Шарпа | `(E[r_p] − r_f) / σ_p` |
| Реальная доходность за период | `(1 + r_p) / (1 + π) − 1` |
| Максимальная просадка | Наибольшее падение капитала относительно предыдущего максимума |

Здесь `r_p` — доходность портфеля за период, `r_f` — годовая безрисковая ставка, `π` — инфляция за период, `k` — число периодов в году. CAGR рассчитывается отдельно от арифметической среднегодовой доходности.

В индексном режиме расчёты выполняются на месячной истории. Выбор квартального или годового отображения меняет детализацию графиков и таблиц. При ручном распределении требуется минимум два месяца доходностей; для автоматического подбора весов — минимум 30 месяцев общей истории. В режиме собственных данных требуется не менее 30 наблюдений после обработки.

## Данные и допущения

| Источник | Использование |
|---|---|
| MOEX ISS | Российские индексы и котировки инструментов Мосбиржи |
| Yahoo Finance через yfinance | Зарубежные индексы и котировки |
| Росстат | Месячный индекс потребительских цен |
| Банк России | Валютные курсы и денежный агрегат M2 |
| Excel/CSV пользователя | Собственные ряды доходностей |

В индексном режиме базовая валюта — рубль. Зарубежные индексы переводятся в рубли по курсу на конец соответствующего месяца, реальная стоимость капитала определяется с учётом накопленного ИПЦ. Ценовые индексы не включают дивиденды; индексы полной доходности учитывают выплаты согласно своей методике.

В режиме загрузки тикеров автоматической валютной конвертации нет: для сопоставимого расчёта нужно выбирать активы в одной валюте. Цены MOEX `CLOSE` не корректируются на дивиденды и дробления; для Yahoo Finance используется `auto_adjust=True`.

Недоступные котировки не заменяются синтетическими данными. Ошибка загрузки обязательных рядов прерывает расчёт; отсутствие M2 сопровождается предупреждением и не мешает анализу портфеля.

## Использование искусственного интеллекта

Проект **частично реализован с помощью генеративного ИИ**. ИИ применялся как вспомогательный инструмент при разработке программного кода и проработке технических решений. Его использование является частью процесса выполнения учебной работы и указано здесь для прозрачного описания разработки.

Основные финансовые расчёты выполняются программными алгоритмами на сервере с использованием NumPy, Pandas и SciPy.

Отдельно в приложении реализована необязательная функция объяснения ошибок через языковую модель, доступную через OpenRouter. Она получает сообщение об ошибке и контекст операции и формирует подсказку. Без настройки этой функции основной анализ остаётся доступным.

## Запуск проекта

### Через Docker

Необходимы Git, Docker и Docker Compose.

```bash
git clone https://github.com/dnndjowow/portfolio-analyzer.git
cd portfolio-analyzer
docker compose up --build
```

Приложение будет доступно по адресу [http://localhost:8080](http://localhost:8080).

Для запуска в фоне используйте `docker compose up -d --build`, для остановки — `docker compose down`.

### Без Docker

Необходимы Python 3.11 и Node.js с npm. После клонирования репозитория запустите сервер из корня проекта:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

На Windows для активации окружения используйте `.venv\Scripts\activate`.

Во втором терминале, из корня проекта, запустите клиент:

```bash
cd frontend
npm ci
npm run dev
```

Клиент: [http://localhost:5173](http://localhost:5173). Интерактивная документация API: [http://localhost:8000/docs](http://localhost:8000/docs). Vite проксирует запросы `/api` на сервер разработки.

### Необязательная диагностика через ИИ

Чтобы включить объяснение ошибок, создайте `.env` в корне проекта:

```dotenv
OPENROUTER_API_KEY=your_openrouter_api_key
```

Модель можно задать переменной `OPENROUTER_MODEL`; если она не указана, используется значение из конфигурации приложения. После изменения настроек перезапустите сервер; для Docker выполните `docker compose up -d`.

При диагностике внешнему сервису передаются сообщение об ошибке и контекст операции, который может включать доходности, настройки, веса портфеля или сведения о загружаемом файле. Ключ хранится на сервере; `.env` исключён из Git и не должен публиковаться.

## Пример работы

1. Откройте приложение и выберите несколько индексов, например MCFTR, RGBITR и S&P 500.
2. Укажите период, начальный капитал и способ определения весов.
3. Выберите правило ребалансировки и выполните расчёт.
4. Сравните номинальную и реальную динамику капитала, доходность и просадки.
5. Измените состав или веса и исследуйте, как изменяется результат.

Для анализа собственных данных откройте «Другие данные». Excel/CSV должен содержать дату или номер периода в первом столбце и доходности активов в остальных. В интерфейсе доступны пустой CSV-шаблон и пример с реальными котировками Мосбиржи; для загрузки котировок требуется интернет.

## Проверка реализации

В репозитории есть тесты оптимизации, расчётов индексного портфеля, обработки данных и API. Для их запуска из корня проекта:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
pytest -q
```

Проверка типов и сборка клиента, также из корня проекта:

```bash
cd frontend
npm ci
npm run build
```

Искусственные ряды используются в автоматических тестах для проверки отдельных сценариев.

## Ограничения и дальнейшее развитие

- Результаты основаны на выбранной истории и не являются прогнозом будущей доходности.
- Не моделируются комиссии, налоги, целые лоты и стоимость ребалансировки.
- Индексный портфель представляет собой модель: прямые покупки индексов и подбор соответствующих фондов не реализованы.
- Месячный шаг индексного расчёта не позволяет оценить внутримесячные просадки.
- Качество и доступность исходных данных зависят от внешних источников.
- Сохранённые портфели доступны в текущем браузере и автоматически не синхронизируются между устройствами.

Возможные направления развития: учёт торговых издержек, проверка стратегий на отдельной исторической выборке, расширение методов оптимизации и подготовка дополнительных учебных примеров.
