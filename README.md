# Portfolio Analyzer

Веб-приложение для расчёта рублёвого портфеля из **любых 2–10 индексов каталога**, с автоматической загрузкой истории, ИПЦ Росстата, курсов ЦБ и отдельным графиком M2. Расширенный режим поддерживает собственные файлы и 2–50 рыночных активов. Backend рассчитывает портфели по модели Марковица, frontend показывает эффективную границу, динамику капитала, просадки и веса активов.

## Возможности

- Четыре режима оптимизации: минимальная волатильность, максимальный коэффициент Шарпа, минимальный риск при заданной доходности и максимальная доходность при ограничении риска.
- Эффективная граница, облако случайных портфелей и точки отдельных активов.
- Сравнение до пяти портфелей на одном графике.
- Интерактивная круговая диаграмма весов с экспортом в PNG.
- Среднегодовая доходность, волатильность, коэффициент Шарпа, CAGR, максимальная просадка и период восстановления.
- Корректировка доходностей всех индикаторов на инфляцию.
- Загрузка Excel/CSV или реальных исторических котировок через Yahoo Finance и MOEX ISS.
- Быстрый пример с реальными котировками девяти акций Мосбиржи и пустой CSV-шаблон.
- Экспорт результатов в Excel и весов в CSV.
- Адаптивный интерфейс, светлая и тёмная темы.
- Автоматическая подсказка по ошибке при настроенной внешней диагностике.

## Быстрый запуск через Docker

Нужны Git, Docker и Docker Compose.

```bash
git clone https://github.com/dnndjowow/portfolio-analyzer.git
cd portfolio-analyzer
docker compose up --build
```

Откройте [http://localhost:8080](http://localhost:8080). Nginx отдаёт frontend и проксирует запросы `/api` в backend.

Для запуска в фоне:

```bash
docker compose up -d --build
```

Управление локальным запуском:

```bash
docker compose logs -f        # просмотр логов, Ctrl+C завершает только просмотр
docker compose down           # остановка и удаление контейнеров
```

Если приложение запущено без `-d`, остановите его через `Ctrl+C`. Повторный запуск выполняется той же командой.

### Настройка диагностики ошибок

В корне проекта создайте файл `.env`:

```dotenv
OPENROUTER_API_KEY=your_openrouter_api_key
OPENROUTER_MODEL=nvidia/nemotron-3.5-lightning:free
```

Не публикуйте `.env` и ключ в GitHub. Ключ передаётся только backend; переменная `OPENROUTER_MODEL` необязательна.

**Без ключа основной анализ работает.** Внешняя диагностика недоступна, а пользователь видит исходную ошибку операции. Для применения изменённого ключа в Docker повторите `docker compose up -d`.

## Индексный портфель — основной режим

Ничего загружать вручную не нужно. На первой странице задайте капитал (по умолчанию 100 000 ₽), месяцы начала и окончания, выберите любые 2–10 индексов, веса и ребалансировку. Нажмите «Рассчитать портфель». После первого расчёта изменения капитала и настроек применяются автоматически с задержкой 500 мс; устаревший результат обозначается до получения нового.

Каталог:

| Код | Индекс | Исходная валюта | Выплаты |
|---|---|---|---|
| IMOEX | Индекс Мосбиржи | RUB | Ценовой |
| MCFTR | Мосбиржа полной доходности | RUB | Полная доходность |
| RGBITR | ОФЗ полной доходности | RUB | Полная доходность |
| RUCBTRNS | Корпоративные облигации | RUB | Полная доходность |
| SP500 | S&P 500 | USD | Ценовой |
| NASDAQ100 | Nasdaq 100 | USD | Ценовой |
| DOW | Dow Jones Industrial Average | USD | Ценовой |
| RUSSELL2000 | Russell 2000 | USD | Ценовой |
| FTSE100 | FTSE 100 | GBP | Ценовой |
| NIKKEI225 | Nikkei 225 | JPY | Ценовой |

Стартовый выбор: MCFTR, RGBITR и S&P 500 с равными весами. Это пример настройки, а не персональная инвестиционная рекомендация. Сумма ручных весов должна быть 100%; отрицательные веса запрещены. Есть автоматические веса: минимальная волатильность и максимальный Шарп по месячной модели Марковица на реальных доходностях. Для автоматического подбора требуется минимум 30 месяцев общей истории; ручной расчёт доступен от двух месяцев. Для Шарпа номинальная безрисковая ставка переводится в реальную через среднегодовой геометрический рост фактического ИПЦ за выборку.

### Данные и методика

- Российские индексы: MOEX ISS, рынок `stock/index`; зарубежные: Yahoo Finance. Ценовые индексы не включают дивиденды, что подписано в каталоге. Полная доходность определяется методикой конкретного индекса.
- **RUB — базовая валюта.** Месячный уровень зарубежного индекса умножается на последний действующий официальный курс ЦБ на конец этого же календарного месяца. Курс делится на номинал валюты (например, котировка за 100 JPY переводится к 1 JPY). Рублёвая доходность: `(1 + r_индекса) × (1 + r_курса) − 1`.
- **Историческая инфляция:** актуальный файл месячного общероссийского ИПЦ обнаруживается на странице [Росстата](https://rosstat.gov.ru/statistics/price). Используется лист `01`, ряд к концу предыдущего месяца, без подмены постоянными 8% или годовой инфляцией. При недоступности ИПЦ возвращается ошибка. Последний месяц расчёта ограничивается опубликованными данными.
- **M2 — только ориентир:** [Банк России, денежные агрегаты](https://www.cbr.ru/statistics/macro_itm/dkfs/monetary_agg/), строка «Денежный агрегат М2», не широкая денежная масса M2X. Уровень на первое число относится к концу предыдущего месяца. Линия нормируется к 100 в начале выборки; пропуски и задержка публикации не заполняются вымышленными значениями. M2 отсутствует в индексах, весах, ковариациях и оптимизации. Сбой M2 не мешает расчёту портфеля и сопровождается предупреждением.
- Начало инвестирования — конец месяца перед выбранным первым месяцем. Конечный месяц включается целиком; незавершённый текущий месяц не используется. При сокращении общей истории это явно сообщается. Пропущенные месяцы внутри истории не заполняются.
- При отсутствии ребалансировки сохраняются условные количества единиц индексов и доли дрейфуют. При ежемесячной ребалансировке исходные веса восстанавливаются перед каждым новым месяцем; при квартальной — в январе, апреле, июле, октябре; при годовой — в январе. Начальное распределение выполняется один раз в начале выборки.
- Реальная доходность портфеля за месяц: `(1 + r_портфеля) / (1 + π_месяца) − 1`. Реальная кривая равна номинальной стоимости, делённой на накопленный ИПЦ. Накопление — перемножение множителей, а не сложение процентов.
- Месяц/квартал/год меняет детализацию графика и таблицы. Ребалансировка, итоговая доходность, годовая волатильность (`std(r_месяц) × √12`) и максимальная просадка остаются рассчитанными на месячной истории. Первый или последний отображаемый квартал/год может быть неполным.
- При изменении капитала масштабируются денежные суммы; процентные доходности и риск остаются прежними. Выход содержит номинальные и реальные показатели, капитал, начальные/конечные веса и CSV по периодам.

Это модельный исторический портфель индексов. Прямые покупки индексов, подбор фондов, целые лоты, комиссии и налоги не моделируются. Шаг расчёта — месяц, внутримесячные просадки не оцениваются.

Публичные исходные ряды кэшируются в памяти с ежедневным обновлением и ограниченным размером кэша. После перезапуска backend история загружается повторно. API-ключи для этих источников не нужны; их доступность и лимиты могут меняться.

### TLS Росстата

Росстат использует сертификат Russian Trusted Sub CA. Для запросов **только к доменам Росстата** используется отдельный TLS-контекст с официальным корневым сертификатом Госуслуг и промежуточным сертификатом 2024 года; цепочка проверена подписью корневого CA. Сертификаты находятся в `backend/certificates/`. Источник корневого: `https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt`; источник промежуточного: `http://nuc-cdp.digital.gov.ru/cdp/subca_ssl_rsa2024.crt`. Проверка TLS не отключается, системное хранилище сертификатов не меняется. При смене цепочки сертификаты нужно обновить из официального источника.

### Дополнительный анализ

Кнопка «Другие данные» открывает существующий режим загрузки файлов/тикеров, эффективной границы, сравнения и Excel-экспорта.

## Как пользоваться

1. **Выберите источник.** По умолчанию доступны тикеры. Кнопка «Попробовать на реальных данных» загружает исторические котировки девяти акций Мосбиржи через MOEX ISS. Требуется доступ к сети; при сбое источника приложение показывает ошибку.
2. **Загрузите данные.** Excel/CSV должен содержать от 2 до 50 рядов доходностей с уникальными названиями. Дата или номер периода располагается в столбце A, доходности активов — начиная со столбца B. Требуется минимум 30 наблюдений после обработки. Можно скачать шаблон из интерфейса.
3. **Настройте обработку.** Укажите единицы доходности, частоту наблюдений, обработку пропусков и инфляцию: постоянную годовую либо отдельный ряд за периоды. При наличии дат доступна агрегация по выбранному таймфрейму.
4. **Оптимизируйте.** Выберите режим и параметры. Для Шарпа вручную задаётся безрисковая ставка; для двух целевых режимов — доходность либо волатильность.
5. **Изучите результат.** Просмотрите веса, показатели, границу, динамику капитала и просадки. Добавьте другие портфели для сравнения.
6. **Экспортируйте.** Сохраните веса в CSV, результаты анализа в Excel или диаграмму весов в PNG.

### Реальные котировки через API

`POST /api/load-tickers` получает историю цен, вычисляет доходности `(P_t / P_{t-1} - 1) × 100` и возвращает готовый датасет. Обязательны только рыночные тикеры; дополнительные макроэкономические ряды не нужны.

- **MOEX ISS**: тикеры с префиксом `MOEX:`, например `MOEX:SBER`, `MOEX:GAZP`, `MOEX:IMOEX`. История загружается постранично из публичного [MOEX ISS API](https://iss.moex.com/iss/reference/). Акции используют режим TQBR, поддерживаемые индексы — рынок index. `CLOSE` — нескорректированная цена: дивиденды и дробления не учитываются, об этом приложение предупреждает.
- **Yahoo Finance через yfinance**: например `SPY`, `TLT`, `GLD`. Загрузка использует [`auto_adjust=True`](https://ranaroussi.github.io/yfinance/reference/api/yfinance.download.html), чтобы получать скорректированные цены. Для примера в одной валюте можно выбрать `SPY, TLT, GLD, QQQ, IWM, EEM, VNQ, LQD, HYG`.
- Выбирайте активы в одной валюте. Валютная конвертация не выполняется; объединение рублёвых и долларовых рядов без перевода в общую валюту не моделирует доходность единого портфеля.
- `start` включается, `end` не включается. Для месячной/недельной/квартальной/годовой частоты неполный последний период исключается. Пропущенные периоды не заполняются устаревшими ценами и не создают фиктивную нулевую доходность.
- Доступность котировок зависит от источника и его лимитов. Ошибка источника возвращается клиенту; синтетическая подмена отсутствует.

Пример тела запроса:

```json
{
  "tickers": ["MOEX:SBER", "MOEX:GAZP", "MOEX:LKOH"],
  "start": "2020-01-01",
  "end": "2024-01-01",
  "frequency": "monthly"
}
```

Скачиваемый CSV-шаблон содержит только названия столбцов. Заполните его собственной историей доходностей: он не содержит вымышленных рыночных данных.

## Методика и ограничения

Backend использует NumPy, Pandas и оптимизатор SLSQP из SciPy. Вес каждого актива ограничен диапазоном `[0, 1]`, сумма весов равна единице. Короткие продажи запрещены во всех режимах, на границе, в случайных портфелях и при сравнении/экспорте ручных весов. Запрос `allow_short=true` и любые отрицательные веса отклоняются с HTTP 422.

| Режим | Что рассчитывается |
|---|---|
| Минимальная волатильность | Портфель с минимальной дисперсией |
| Максимальный Шарп | Максимум отношения избыточной доходности к риску при заданной безрисковой ставке |
| Эффективный риск | Минимальная волатильность при заданной ожидаемой доходности |
| Эффективная доходность | Максимальная ожидаемая доходность при волатильности не выше заданной |

Эффективная граница строится от глобального минимума дисперсии до максимальной достижимой доходности. Облако использует те же годовые средние и ковариационную матрицу. В него входят случайные неотрицательные портфели и сами оптимальные портфели границы. При пересечении облака отрезком между узлами добавляется оптимум для соответствующей доходности, пока расхождение риска не станет меньше `1e-7`. В интерфейсе узлы соединяются прямыми отрезками, без сглаживания. `n_points` задаёт начальную сетку; после уточнения точек может быть больше. `n_samples` задаёт число случайных портфелей, узлы границы добавляются к ним отдельно.

Ввести целевое значение коэффициента Шарпа как ограничение сейчас нельзя — вручную задаётся безрисковая ставка.

| Показатель | Расчёт |
|---|---|
| Реальная доходность | `(1 + r) / (1 + π) − 1` |
| Инфляция за период из годовой | `(1 + π_год)^(1/k) − 1` |
| Ожидаемая среднегодовая доходность | `mean(r_p) × k` |
| Годовая волатильность | `std(r_p) × √k` |
| Коэффициент Шарпа | `(E[r_p] − r_f) / σ_p` |
| Кривая капитала | Начальное значение 100, затем последовательное умножение на `(1 + r_p)` |
| Максимальная просадка | Наибольшее падение капитала относительно предыдущего максимума |
| Максимальный период восстановления | Самый длинный период от пика до возврата к нему; незавершённое восстановление учитывается до конца выборки |

`k` — число периодов в году: 252, 52, 12, 4 или 1. CAGR рассчитывается отдельно от арифметической среднегодовой доходности. Номинальная безрисковая ставка пересчитывается в реальную, если включена соответствующая настройка.

Результаты — оценки по загруженной истории. Кривая использует постоянные веса, что соответствует ребалансировке каждый период. Комиссии, налоги и стоимость ребалансировки не моделируются. Сравнение строится на одном наборе данных.

Проверяются число индикаторов, количество наблюдений, конечность значений и ненулевая дисперсия рядов. Недостижимые цели оптимизации возвращают ошибку. Если все активы уступают безрисковой ставке, максимальный Шарп может быть отрицательным; приложение показывает предупреждение.

Портфели сохраняются в IndexedDB текущего браузера. Сервер не хранит их как пользовательскую учётную запись; между устройствами они автоматически не синхронизируются.

## Диагностика ошибок

При сбое загрузки, оптимизации, построения границы, сравнения или экспорта пользователь сначала видит исходную ошибку. Если диагностика настроена, интерфейс автоматически запрашивает объяснение и показывает **«Подсказку по ошибке»** с вероятной причиной и шагами проверки.

Backend обращается к OpenRouter. Передаются этап операции, сообщение об ошибке и контекст:

- При ошибке расчёта — доходности, настройки и, при наличии, веса портфелей.
- При ошибке загрузки файла — имя, размер и тип файла.
- Большие ряды сокращаются до первых 60 и последних 40 наблюдений, если контекст превышает ограничение размера.

В интерфейсе есть уведомление о возможной передаче данных внешнему сервису диагностики. Название провайдера и ключ в пользовательской подсказке не отображаются.

Модель объясняет сбой, но **не исправляет код, не выполняет команды и не заменяет финансовые расчёты**. Если ключ отсутствует, провайдер недоступен или превышен лимит, подсказка может не появиться. Диагностика ограничена: не чаще одного запроса за 15 секунд и не более 20 запросов в час на IP-адрес, который видит backend.

## Развёртывание на собственном сервере

Для Ubuntu с установленными Docker и Docker Compose базовый запуск из репозитория:

```bash
git clone https://github.com/dnndjowow/portfolio-analyzer.git /opt/portfolio-analyzer
cd /opt/portfolio-analyzer
# Создайте .env, если нужна диагностика ошибок.
docker compose up -d --build
```

Базовая конфигурация публикует HTTP на порту `8080`. Для HTTPS нужна отдельная настройка обратного прокси и сертификата.

### Подготовленные архивы серверного деплоя

Для текущего развёртывания дополнительно подготовлены `portfolio-analyzer-deploy.tar.gz` и `portfolio-https.tar.gz`. **Серверные скрипты и HTTPS-конфигурация находятся в этих архивах и пока не входят в репозиторий.** Команды ниже применимы после их распаковки в `/opt/portfolio-analyzer`.

Первичная настройка приложения и ключа:

```bash
cd /opt/portfolio-analyzer
bash setup-assistant.sh
```

Включение HTTPS после распаковки HTTPS-архива:

```bash
bash enable-https.sh
```

Подготовленная конфигурация рассчитана на `31.77.206.83`. Caddy получает сертификат Let's Encrypt для этого IP, перенаправляет HTTP на HTTPS и автоматически продлевает сертификат. Порты TCP `80` и `443` должны быть доступны извне и свободны для Caddy. После успешной проверки HTTPS порт `8080` привязывается только к `127.0.0.1`.

Управление серверной установкой с HTTPS:

```bash
bash compose-server.sh ps
bash compose-server.sh logs -f
bash compose-server.sh up -d --build
bash compose-server.sh down
```

Используйте этот скрипт, чтобы учитывались все конфигурации Compose. Не удаляйте Docker volumes Caddy: в них хранятся сертификаты и данные для их продления.

Для проверки ресурсов:

```bash
docker stats --no-stream
free -h
```

Контейнеры в подготовленной серверной конфигурации используют `restart: unless-stopped`. При включённой службе Docker приложение запускается после перезагрузки сервера. Закрытие SSH-сессии не останавливает запуск в фоне.

## Render

В репозитории есть `render.yaml`. Создайте **Blueprint** из GitHub-репозитория: конфигурация описывает два сервиса — `portfolio-api` (Python/FastAPI) и `portfolio-web` (Static Site).

- `OPENROUTER_API_KEY` задайте как секретную переменную backend, если нужна диагностика.
- Адрес API передаётся frontend через `VITE_API_URL`.
- Для ограничения CORS задайте backend переменную `CORS_ORIGINS` с адресом опубликованного frontend.

Доступность тарифов и условия размещения проверяйте в Render перед созданием сервисов.

## API

| Метод | Endpoint | Назначение |
|---|---|---|
| GET | `/api/index-catalog` | Каталог 10 индексов |
| POST | `/api/index-portfolio` | Рублёвый портфель, ИПЦ, ребалансировка и отдельная линия M2 |
| GET | `/api/health` | Проверка доступности backend |
| POST | `/api/upload` | Загрузка Excel/CSV, датасет и превью |
| POST | `/api/load-tickers` | Исторические котировки и доходности рыночных активов |
| POST | `/api/optimize` | Веса оптимального портфеля и показатели |
| POST | `/api/efficient-frontier` | Граница, случайные портфели и точки активов |
| POST | `/api/portfolio/metrics` | Показатели для заданных весов |
| POST | `/api/compare` | Кривые и показатели до пяти портфелей |
| POST | `/api/export` | Экспорт результатов в Excel |
| POST | `/api/support/diagnose` | Подсказка по ошибке |

Старый маршрут `/api/assistant/diagnose` сохранён для совместимости и скрыт из OpenAPI. Переданные `returns` обрабатываются на backend с учётом единиц, частоты и инфляции в каждом запросе.

## Структура проекта

```text
portfolio-analyzer/
├── backend/

│   ├── config.py               # Настройки окружения и константы

│   ├── data_loader.py          # Источники данных, обработка и инфляция
│   ├── assistant_service.py    # Внешняя диагностика ошибок

├── frontend/
│   └── src/
│       ├── components/         # Формы, графики, приветственный экран
```

## Проверки для разработки

Тесты backend:

```bash
cd backend
pip install -r requirements-dev.txt
pytest -q
```

Сборка frontend:

```bash
cd frontend
npm ci
npm run build
```

Тесты проверяют неотрицательные веса, отклонение запроса на шорты и исключённого показателя, достижимость целей, совпадение точек облака и границы, отсутствие пересечения облака линией, парсинг файлов, пагинацию MOEX и обработку цен Yahoo. Искусственные ряды используются только в изолированных автоматических тестах.
